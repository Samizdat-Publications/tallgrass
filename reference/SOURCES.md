# Reference images: sources and approval

The scorecard (`tools/scorecard.py`) compares captures against the images in `reference/shots/`. This file records where each
one came from and whether the owner has approved it as a reference.

**Rule: a new reference counts only after the owner approves it.** Until then it is listed here as PROVISIONAL. A provisional
reference may be scored for information, but a score against it is not a target, and nobody tunes the look toward it.

## Baselines and history (not references)

- `reference/baseline/<id>.jpg` (JPEG quality 92) and `reference/baseline.json`
  (`{ commit, date, shots: { id: { sha256, pixels_sha256 } } }`) hold the last accepted capture of each shot. They are written
  only by `tools/scorecard.py <run_dir> --accept`, after the lead has looked at the run. The sha256 is of the original lossless
  capture file, so an unchanged capture reads as `identical`.
- `reference/baseline/local/<id>.png` is the same accepted capture, lossless (the exact capture bytes). `--accept` writes it
  too. It is gitignored: renders differ slightly between GPUs and drivers, so the lossless copy only means something on the
  machine that accepted it. It is used only when its pixels match `pixels_sha256` in `baseline.json`; a stale copy (another
  machine accepted since) is ignored.
- Drift status per shot, in the scorecard summary.md, summary.json and contact sheet:
  - `identical`: same file sha256 or same decoded pixels as the baseline.
  - `noise`: compared with the local PNG, mean absolute difference <= 0.5 and at most 0.25% of pixels with a channel
    difference over 8. These are the cross-load noise thresholds of `tools/shots.mjs --verify`, measured 2026-11-12 (two
    page loads of the same shot: mean <= 0.17, share over 8 <= 0.10%; most shots are not byte-identical across loads).
  - `noise (jpeg)`: no usable local PNG, compared with the JPEG under looser thresholds (mean <= 2.0, share over 8 <= 3%),
    since JPEG compression error adds to the noise. Run `--accept` once on this machine to get the stricter lossless check.
  - `drifted`: anything over those thresholds (or a size change). `--fail-on-drift` fails only on this.
  - `new`: no baseline for the shot.
- `reference/score_history.json` is a JSON array with one object per scorecard run:
  `{ stamp, commit, total, shots: { id: score }, drifted: [ids] }`.
