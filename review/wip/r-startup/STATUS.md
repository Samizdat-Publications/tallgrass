# r-startup status (WIP, stopped early at owner shutdown)
1. Profile: cold start was 28 to 70 s, all of it shader compile (104 programs, ~25 of them 170-230 KB; ANGLE D3D11 compiles them one at a time when first drawn). JS setup is only 2.4 s. Marks: src/startmarks.ts (window.__marks, __frameMs), tools/loadtime.mjs.
2. Change: Engine.compileScene() / compileEarly() / prime() (src/render/engine.ts) enable KHR_parallel_shader_compile, compile every material plus the shadow depth materials in one burst, and wait for the driver. main.ts calls prime() before engine.start() (?prime=0 restores the old path). On a quiet machine cold ready went 47 s -> about 12 s (noisy: other builders were capturing; early compile of terrain/water/trees won 3 of 3 A/B pairs).
3. BUG found: a "dry frame" (post.render with draws stubbed, to create post/GTAO programs) intermittently leaves NaN in shared uniforms (uCloud, uOvercast, uRainbow, uHaze) so the scene renders black. It is now off by default (?dryframe=1 turns it on). With it off, 3 of 3 cold runs rendered correctly, but I have NOT re-run stills or a visual check of the final default build, and the ~27 post-pass programs now compile lazily at the first frames (slower than the 12 s figure, unmeasured).
